# Experimental Usenet playback

Usenet playback is integrated on `dev` in the Kotlin engine. The current full-debug build is **ReSeq IPTV Debug**, package `io.github.abbaskip.nuvioreseq.iptvdebug`, and uses its own Android app data. The older **ReSeq Usenet Test** preview is a historical build, not the current build target.

See [implementation, limits and provenance](usenet-upstream-review.md) for the current capability summary and upstream revision mapping.

## Playback path

1. The stream mapper reads Stremio's `nzbUrl`, `servers`, `fileIdx`, and `fileMustInclude`. The selector accepts a string or an array of filename hints, including slash-delimited regular expressions with optional case-insensitivity. An existing direct video URL takes precedence.
2. Selecting a Usenet result fetches its HTTP(S) NZB and orders the article IDs by segment number. The engine connects to an add-on-supplied NNTP or NNTPS provider. NNTPS validates certificate trust and hostname before authentication. The separate, shared add-on discovery client still accepts self-signed certificates for existing installations. Its add-on HTTP breadcrumbs retain the host and omit configured URL paths and query strings.
3. The reader decodes yEnc articles, validates supplied part checksums and locates requested bytes from the yEnc ranges. When NZB subjects lack usable filenames, a bounded first-article probe can recover video and volume names from yEnc headers. NZB byte counts describe posted data and serve only as file-size estimates. The decoded-article cache retains 16 MiB on low-memory devices or 32 MiB otherwise, plus a separate bounded header-slice LRU (at most 8 MiB). Shared account pools honour the add-on's `/N` connection allowance up to 12, default to two when absent, and cap the process at 24 sockets. Bounded parallel read-ahead leaves demand capacity; one-connection providers retain pipelining. Missing articles trigger fallback to the other supplied providers.
4. For stored RAR4 and RAR5 files, the reader examines the volume headers, checks header CRCs, joins split file extents and maps video offsets back to the corresponding articles. It supports `.partNN.rar`, `.rar/.r00` (including `.r100`), and signature-checked numeric sets such as `.rar.001`. Duplicate filenames prefer a complete NZB segment list, then the larger posted size. Regular stored RAR sets map from the first, second and ending volume headers; intermediate headers are checked before their bytes are served. A layout mismatch rebuilds from real headers and preserves the advertised payload size, or fails explicitly. Encrypted headers and unsupported main-header metadata use the checked scan path. Stored RAR5 payloads and headers can be decrypted on demand when the NZB supplies the password and the archive includes a password check. PAR2 file descriptions can restore hidden filenames. Single-member RAR5 volume chains can also be ordered by their internal volume numbers; anonymous RAR4 chains retain NZB order. Unknown heads are probed in batches of eight, with up to the NZB file limit (4096) considered. Retained header slices avoid repeatedly downloading evicted volume heads.
5. The reader also handles stored 7z members with plain or LZMA/LZMA2-compressed indexes, split `.7z.001` archives, numbered video fragments and a single stored archive inside another supported archive. Split 7z/video streams initially open their first and last volumes; middle decoded sizes are checked on first use. The XZ library only decodes the bounded archive index.
6. The player receives a random, session-specific HTTP URL bound to IPv4 loopback. It supports HEAD, GET and single byte ranges. Source and episode switching use the same resolver as the initial selection. The last-link cache skips these temporary URLs. Provider login data stays out of the player URL.

## Startup and buffering diagnostics (November 2026)

Up to two preferred-provider logins start while the NZB downloads. Warm-up failures do not replace demand errors, and cancellation closes both HTTP and NNTP work. Parsed NZBs are cached only in memory for 30 minutes, keyed by URL and request headers, with at most four entries and a combined 12 MiB decoded-source budget. Changed signed URLs or headers miss the cache.

Strict direct episode matches are checked first, followed by archive sets whose names match the requested episode. Archive entries are walked lazily; a matching entry can open without indexing unrelated sets. Explicit indexes retain expanded NZB order, and the existing full-inventory fallback remains available for a single unmarked video. A filename filter cannot override a conflicting explicit episode marker. Skipping an unselected split entry requires a matching final-part header.

The low-memory profile (`isLowRamDevice` or memory class below 192 MiB) uses a 16 MiB article cache, a six-article window and an estimated 8 MiB window cap. Normal devices use 32 MiB, twelve articles and 16 MiB. Speculation also reserves a worst-case 4 MiB per in-flight load against three quarters of the article budget, so the actual concurrent window can be smaller. It never waits for or evicts a pool slot, and leaves one account/global slot for demand. Old windows finish within the existing read deadline after a seek; no new work is added to them. Volume-boundary reads prime the next volume's head. The socket reader uses a 64 KiB input buffer.

Filter logcat on `UsenetStartup`. Each resolve logs one summary containing monotonic stage offsets (`nzb_request`, `nzb_received`, first new login, selection start/end and session start), archive kind, the preferred provider's clamped allowance and source (for example `conns=5 (addon)` or `conns=2 (default)`), volume/file counts, downloads, decoded bytes, cache hits, flight joins and refetches. The allowance updates on successful provider fallback. It is the configured ceiling; instantaneous socket use can be lower. A reused authenticated connection may have no new-login mark. The first valid GET logs its prefix wait separately. Logs contain no source URLs, hosts, credentials, article IDs, filenames or exception text.

The tests include synthetic RAR4/RAR5 sets, the pinned upstream fourteen-volume padded-width fixture, shuffled anonymous sets, real encrypted fixtures and loopback concurrency/cancellation checks. They assert byte equality and article counts, not TV performance. Shuffled anonymous sets still inspect their headers to establish a complete unambiguous order; fully lazy shuffled discovery remains future work. RAR5 encrypted headers deliberately remain outside arithmetic prediction.

## Host validation

Run `gradlew.bat :app:testFullDebugUnitTest --tests "com.nuvio.tv.core.usenet.*" -PuseLocalFfmpegDecoder=false` with the project JDK and Android SDK. The tests start temporary loopback servers with synthetic logins. The TLS test creates its own short-lived certificate using the JDK's keytool.

The November 11, 2026 final host run completed 72 Usenet tests (71 passed, one opt-in profiler skipped) and the full 3,456-test suite (3,454 passed, two skipped), with zero failures or errors. Run the full suite by omitting the `--tests` filter.

The test resources contain a four-second 96×64 MP4 made from generated colour frames. WinRAR 7.22 produced the two 4 KiB-target RAR5 volumes and the compressed and encrypted rejection samples. The two legacy RAR4 fixtures use stored file blocks wrapping the same MP4. The newer RAR5 password fixtures use the synthetic password `FixtureOnly5`. The 7z fixtures wrap the same media using libarchive’s Copy method, including a two-episode pack with independently compressed LZMA and LZMA2 indexes. Host tests compare bytes returned by Nuvio with the original MP4, including requests near EOF and across article and volume boundaries.

To build the current debug APK, supply the approved project values for `NUVIO_SUPABASE_URL` and `NUVIO_SUPABASE_ANON_KEY` in an ignored local properties file and run `gradlew.bat :app:assembleFullDebug -PuseLocalFfmpegDecoder=false`. The universal APK is under `app/build/outputs/apk/full/debug/`. The project's `scripts/verify_apk_services.py --backend-only` checks compiled APKs against the configured backend inputs.

## Manual test

1. Open the current **ReSeq IPTV Debug** build and configure the Stremio-compatible add-on and Usenet service you intend to use. An add-on that returns `nzbUrl` plus `servers` exercises this feature. A debrid or WebDAV result that already points at playable HTTPS video exercises the standard player path.
2. Play a directly posted video, then try a stored multipart RAR. Seek forward, back, and near the end. Check picture, audio, and subtitle selection.
3. Try a season pack. Check the episode opened from the stream list, then switch episodes from the player. Try a second Usenet result and an ordinary HTTPS result afterward.
4. Record time to first picture, seek delay, and any displayed error. A source description and archive type are sufficient for reporting. Omit provider URLs, NZB download URLs, manifest URLs, and login details.

## Further work

- Measure time to first frame, memory use and sustained throughput with real providers and large multi-volume releases. Regular RAR preparation now reads three volume heads, with checked scanning for layouts that do not qualify. Compare source handoff and seeking at one, two and eight provider connections; host article counts do not establish real-world startup latency.
- Expand coverage for obfuscated filenames, ambiguous or damaged season packs, and capture real-world selection differences when extending selection behavior. Explicit indexes use NZB order with archive entries expanded in place. Episode selection uses the add-on request coordinates and filename markers. Ambiguous packs can require an explicit add-on selector.
- Validate Android player handoff, source switching, long pauses and exit on the user's chosen device during manual testing. Session links expire after two hours without reads or when the internal player releases them.
- FTP(S) NZB retrieval, compressed video payloads, encrypted RAR4 and 7z archives, PAR2 repair, disc images and standalone Stremio `rarUrls` sources are outside the implemented path. An add-on-supplied NNTP configuration is required.
- Review further upstream behavior when extending the Kotlin archive or throughput paths. It also includes independent indexer and provider settings. [Upstream proposal](https://github.com/NuvioMedia/NuvioTV/pull/4426)

Protocol references include the [Stremio stream format](https://stremio.github.io/stremio-addon-sdk/api/responses/stream.html), [NNTP specification](https://datatracker.ietf.org/doc/html/rfc3977) and [RAR5 format](https://www.rarlab.com/technote.htm).
